작성일: 2026-09-06. 상태: 구현·실제 3개 발행·화면/PDF 품질 점검 완료. PR/CI 진행은 QA 문서에 기록.
기준: PR #52 병합 커밋 `c1394172fdd19cef87bde47ff1688cf31020e5d2`와 그 PR 작업 트리에서 확인한 코드. 구현 시작 시 최신 main과 관련 변경을 다시 확인한다. 현재 원래 작업 공간의 다른 변경은 건드리지 않는다. OMO 및 하위 에이전트 없이 진행한다.

## 1. 제품 결정

전체 리서치의 첫 번째 '위원회 판단' 다음에 두 번째 챕터 '차트 구조와 다음 움직임'을 추가한다. 같은 보고서 안의 독립 분석 페이지이며, 새로운 리서치 실행 상품이나 별도 전체 화면 서비스 생성은 이번 범위에 포함하지 않는다. 시장 팀 리서치에도 같은 컴포넌트를 사용한다. 다른 단일 팀 리서치에는 June을 추가 호출하거나 차트 페이지를 강제로 넣지 않는다.

데스크톱은 요청한 순서대로 1시간/4시간, 일봉/주봉의 2×2 구성이다. 분석 순서는 주봉 → 일봉 → 4시간 → 1시간이다. 작은 화면은 1열로 바꾸고 네 시간대를 모두 읽을 수 있게 한다. 보고서 화면의 다크/라이트 선택을 그대로 따른다.

사용자가 얻어야 하는 답은 다음 다섯 가지다.

1. 현재 가격은 큰 추세의 어디에 있는가?
2. 가장 가까운 의미 있는 지지·저항/매물 후보 구간은 어디인가?
3. 다음 봉에서 어떤 반응을 기대하며 무엇을 확인해야 하는가?
4. 어느 가격과 종가 조건에서 이 해석이 무효가 되는가?
5. 네 시간대가 같은 이야기를 하는가, 서로 다른 국면을 보여 주는가?

다음 봉의 정확한 OHLC나 검증하지 않은 승률을 생성하지 않는다. 다음 한 개의 확정봉을 1차 관찰 대상으로 삼고, 필요할 때 후속 1~3개 봉의 확인 경로를 설명한다. 가격 접근만으로 돌파/이탈이 확정되었다고 쓰지 않는다. 종가 확인과 되돌림 재확인 조건을 구분한다.

## 3. 데이터 계약과 기준 시점

### 수집

- 공급사의 기존 `/v3/symbols/{symbol}/series` 사용. 1h/4h는 공급사 native 봉을 사용하며 단순히 1시간봉 네 개씩 합치지 않는다.
- 주봉은 `bar_type=week`, `bar_interval=1`로 직접 요청한다. 실제 계정의 응답·봉 경계·조정 의미는 구현 첫 단계에서 한 종목으로 확인한다. 문서 지원만으로 실제 계정 동작을 검증했다고 기록하지 않는다.
- 초기 목표 보관 개수는 1h 500, 4h 500, 1d 1,000, 1w 500이다. 화면의 최초 표시 범위는 대략 최근 120/120/180/156봉으로 별도 지정한다. 공급사는 dp를 500 단위로 올릴 수 있고 일·주봉에서 더 긴 데이터를 반환할 수 있으므로 수신 개수와 보관 개수를 분리한다.
- 네 시간대는 병렬 수집하고 개별 결과를 보존한다. 현재의 3개 고정 튜플/Promise.all 가정은 시간대별 `available | partial | unavailable` 결과 구조로 정리하고 collector 및 파생 분석 호출부를 함께 수정한다.
- 동일 종목·기준 시각의 일봉/시세 수집은 기존 캐시·수집 결과를 재사용한다. 주봉 외에 중복 네트워크 호출을 만들지 않는다.
- 현재 사용하는 `split=true`, `dadj=false`, `extended=false`를 일관되게 유지한다. 공급사 세션 정보와 거래소 시간대를 보관한다. 기존 권한 정책이 화면에 허용하는 데이터 범위와 새 캔들 표시 범위를 맞춘다.

### 확정봉과 재현성

- `analysisAsOf`는 수집 스냅샷 기준 시각이다. 보고서가 열릴 때 현재 시세를 다시 불러와 과거 작도에 섞지 않는다.
- 분석은 그 시각까지 마감된 봉만 사용한다. 진행 중인 마지막 봉은 차트에서 구분해 보여 줄 수 있으나 스윙 확정·돌파 확정·지표 기준에는 포함하지 않는다.
- 주봉 마감, 휴장·조기 폐장, DST를 공급사 메타데이터와 거래소 캘린더로 처리한다. 봉 시작 시각만 보고 확정봉으로 간주하지 않는다.
- 원천 봉의 시각/가격/거래량, 공급사, 조정 방식, 데이터 해시, 알고리즘 버전, 기준 시각을 보관한다. 표시는 반올림하되 계산·근거 값은 원래 정밀도를 보존한다.
- 미래 봉을 잘라 낸 데이터로 계산했을 때 당시 결과를 재현할 수 있어야 한다. 스윙의 기준 봉 시각과 '그 스윙이 확인된 시각'을 별도 기록한다.
- 주봉 부족 시 유효한 일봉을 주 단위로 집계할 수 있지만 실제 거래주 기준이며 주초 데이터가 잘린 첫 주와 미완료 주를 제외한다. 이 경로는 `derived_from_daily`로 표시하고, 필요한 200개 봉이 없으면 200주 이동평균은 생략한다.

### 새 산출물

새 `TechnicalChartSnapshotV1` 계약을 `src/research/domain/technicalChart.ts`에 둔다. 네 시간대별 캔들/워밍업 정보, 파생 지표, drawing 목록, 해석용 fact 목록, 스냅샷 기준과 상태를 포함한다. 차트 원본과 공개용 캔들 필드는 구분한다. 공급사 원문 응답 전체를 API로 내보내지 않는다.

각 drawing은 ID, 종류, 시간대, 가격·시간 앵커, 생성/확인 시점, 근거 봉 ID, 활성/재시험/무효 상태, 선정 이유를 가진다. 생성 이후 화면 크기나 줌에 따라 앵커가 바뀌지 않는다. UI와 PDF는 동일한 drawing 데이터에서 렌더링한다.

## 4. 작도 엔진의 v1 규칙

아래 수치는 첫 버전의 재현 가능한 기본값이며 예측력이 검증되었다는 의미가 아니다. 알고리즘 버전과 함께 저장하고 실제 사례에서 과도한 선/무의미한 선이 나오는지만 먼저 점검한다.

| 작도 | 생성 규칙 | 선정·무효화 |
| --- | --- | --- |
| 스윙 | 기본 좌우 2개 확정봉으로 지역 고점/저점을 확인. 실제 확인은 오른쪽 2개 봉이 끝난 뒤 | 단순 근접 고저점을 중복 생성하지 않고 최소 간격·ATR 기준으로 작은 흔들림 정리 |
| 지지·저항 | 확인된 스윙 가격을 `max(2틱, 0.25×ATR14)` 허용 폭으로 묶어 가격대 생성 | 서로 떨어진 반응 횟수, 최근 반응, 움직임의 크기, 현재가와의 거리를 기준으로 선정. 기본 지지 1~2개/저항 1~2개 |
| 추세선 | 시간 간격이 있는 두 개 이상의 같은 종류 스윙을 연결. 세 번째 접촉은 추가 근거 | 캔들 몸통을 반복 관통하는 선 제외. 두 접점만 있으면 잠정, 세 번째 확인 시 검증됨. 종가 이탈 시 상태 변경 |
| 평행 채널 | 유효한 추세선과 같은 기울기를 쓰고 반대편 확인 스윙으로 폭 설정 | 유효한 반대편 반응이 없으면 채널 생략. 채널과 원래 추세선을 독립적인 두 근거로 중복 가산하지 않음 |
| 오더블록 후보 | 확인된 스윙을 종가로 돌파하는 변위 구간에 앞선 마지막 반대색 봉을 후보로 선택. 초기 변위 기준은 3봉 이내 1.5×ATR14, 범위는 해당 봉의 고가~저가 | 후보 생성 근거/돌파 봉/첫 재방문 시점 보관. 먼 경계를 종가로 넘으면 무효. 이미 소진된 후보는 기본 화면에서 제외. OHLCV로 기관 주문을 확인했다고 표현하지 않음 |
| 이동평균 | SMA20·50 기본, SMA200 선택 표시. 계산에 충분한 확정봉이 있는 경우만 생성 | 정렬·기울기·가격 이격을 문장 근거로 사용. 각 선을 별도 추세 표로 중복 나열하지 않음 |

거래량은 차트 아래 작은 막대로 표시하고 평균 대비 반응의 보조 근거로 사용한다. RSI/MACD 패널을 추가해 화면을 복잡하게 만들지 않는다. ATR은 구간 폭·노이즈·거리의 기준으로 사용한다.

한 차트의 기본 표시 예산은 이평선 2개, 주요 지지/저항 구간 합계 최대 4개, 추세선 또는 채널 1세트, 오더블록 후보 최대 2개다. 겹치는 구간은 통합하고 필요 없는 종류는 생략한다. 추세선과 채널을 동시에 중복해서 그리지 않는다. 전체 후보는 펼쳐 보기로만 제공한다.

v1 가격축은 선형으로 통일한다. 봉 사이의 휴장 시간을 길이로 오해하지 않도록 추세선은 거래 봉 인덱스 기준으로 계산한다. 웹/정적 출력에 같은 좌표 변환을 쓴다. 추후 로그 축을 넣을 때는 분석·투영·렌더링의 기울기 계산을 함께 확장한다.

## 5. '다음 봉' 설명의 구조

각 시간대는 다음을 가진다.

- 관찰: 확인된 구조와 현재 위치. 예: 상승 채널 하단과 일봉 지지 구간이 겹침.
- 기본 경로: 해당 구간을 유지했을 때 먼저 확인할 반응/다음 가격대.
- 대안 경로: 종가 이탈 또는 돌파 실패 시 다시 확인할 구간.
- 무효화: 어느 시간대의 종가가 어느 drawing 경계를 넘는지.
- 시간 범위: 다음 1개 확정봉, 후속 확인에 필요한 경우 최대 3개 봉.

조건/대상 가격은 drawing과 지표의 ID를 참조해 서버가 채운다. 모델이 새 가격 목표나 무효화 가격을 숫자로 만들어 내도록 하지 않는다. 다음 봉 그림을 확정된 미래 캔들처럼 그리지 않는다. 마지막 확정봉 오른쪽의 얕은 음영/짧은 점선 화살표로 두 조건부 경로를 구분한다.

종합 판단은 주봉의 큰 국면 → 일봉의 주요 구조 → 4시간의 셋업 → 1시간의 확인 순서다. 네 개의 신호를 4표로 세거나 '3/4 상승=75% 상승 확률'로 바꾸지 않는다. 같은 캔들 기반 지표의 중복도 근거 수로 부풀리지 않는다.

충돌 예시 문장: '주봉 상승 구조는 유지되지만 일봉 저항 아래에서 4시간 조정이 진행 중이다. 1시간 반등은 단기 회복으로 보고, 4시간 종가가 저항을 회복해야 상위 흐름 재개로 해석한다.' 실제 가격과 참조 작도는 해당 실행의 산출물로 채운다.

횡보장은 억지로 상승/하락 결론을 내지 않고 상·하단에서 확인할 조건을 제공한다. 모든 사례에 오더블록·채널을 반드시 만들지 않는다. 작도 강도는 높은/보통/약한 근거로 표현할 수 있지만 승률로 표시하지 않는다.

`캔들 수집 → 확정봉 정리 → 지표/스윙/작도 후보 계산 → June의 선택과 해석 → 검증된 차트 산출물 → 최종 보고서 페이지 02`

- June의 기존 specialist 호출에 작은 구조화 입력을 추가한다. 모든 원본 캔들을 문장으로 쏟아 넣지 않고 각 시간대의 핵심 구조/지표/drawing 후보와 증거 ID를 전달한다.
- June은 시간대별 중요한 후보, 기본/대안 경로, 무효화 조건과 네 시간대 종합 해석을 작성한다. 선택 가능한 ID와 수치는 이미 존재하는 데이터로 제한한다.
- 모델 출력의 기존 필수 memo와 새 선택 차트 해설은 독립적으로 검증한다. 선택 해설 한 항목이 잘못되었다고 기존 정상 memo 전체를 거부하지 않는다. 엄격한 JSON 스키마에서도 이 분리가 유지되도록 runner 출력/수신 처리를 함께 설계한다.
- 기본 LLM 호출 수는 기존 June 호출 한 번을 유지한다. 네 시간대별 4회 호출, 차트 별도 회의, 추가 의장 합성은 만들지 않는다.
- 시장 팀 대표는 상위/하위 시간대의 충돌과 가격 조건을 기존 팀 합의에 사용한다. 의장은 전체 투자 판단과 기술적 타이밍 판단이 다를 때 차이를 한 문장으로 설명할 수 있다. 기술적 반등을 펀더멘털 호전의 증거로 바꾸지 않는다.
- 잘못된 drawing 참조/문장 하나는 제거하거나 규칙 기반 해설로 대체한다. 자동 문장은 계산 결과로 확인한 구조와 조건만 설명한다. 과도한 문체 검사로 발행을 실패시키지 않는다.

## 7. 저장·API·발행 안정성

- 차트는 보고서 발행 전에 수집된 동일 스냅샷에서 만든다. 완성된 산출물은 immutable CAS artifact로 저장하고 보고서에는 선택적인 `technicalChart` manifest를 연결한다. manifest에는 버전/해시/상태/기준 시각을 둔다.
- 보고서 저장·변환·복원·PDF 경로가 이 선택 필드를 보존하도록 함께 수정한다. 이전 보고서에 필드가 없어도 정상 열려야 한다. 과거 보고서 조회를 계기로 새 시세 분석을 자동 실행하지 않는다.
- 차트 읽기는 보고서 ID/버전에 귀속되는 기존 인증·공개 보고서 정책을 그대로 사용한다. 임의 artifact 경로나 임의 공급사 쿼리를 받지 않는 bounded endpoint로 공개 허용된 차트 데이터를 반환한다.
- 모든 차트 데이터가 정상일 때 `ready`; 일부 시간대/그리기가 빠지면 `partial`; 사용할 근거가 없으면 `unavailable`. 이 상태는 차트 페이지의 상태이며 보고서 전체의 성공/실패와 별개다.
- 주봉 API 오류는 주봉 카드에만 반영한다. 오더블록이 없다는 이유로 실패 처리하지 않는다. 텍스트 해설 오류는 유효한 작도와 계산된 조건 문장으로 복구한다.
- 차트 생성/저장에 실패하면 해당 선택 산출물을 제외하고 핵심 리서치는 기존 경로로 발행한다. 유효하지 않은 manifest를 게시하지 않는다. 이후 자동으로 내용을 바꾸지 않고 명시적 새 보고서 버전에서만 갱신한다.
- UI의 차트 모듈 로딩/렌더링 오류는 해당 카드나 페이지에서 처리한다. 발행된 보고서를 여는 조건에 차트 렌더링 성공이나 모든 애니메이션 종료를 추가하지 않는다.
- 단계별 시간, 이용 가능한 시간대, 표시 작도 수, fallback 여부와 이유를 기록한다. 품질 점수 하나를 새로운 발행 게이트로 추가하지 않는다.

## 8. 화면과 차트 라이브러리

TradingView의 Lightweight Charts 5.x를 권장한다. 정확한 버전은 구현 시 공식 릴리스 확인 후 고정한다. 직접 수집한 캔들을 넣고 primitives로 선·채널·구간을 렌더링한다. 공식 문서의 attribution notice와 링크 조건을 반영한다.

화면 구성:

1. 챕터 02 제목, June의 담당 표시, 기준 시각, 전체 흐름 한 문장.
2. 2×2 차트. 카드마다 시간대/국면, 캔들·거래량·작도, 핵심 구간, 다음 봉 조건 한두 문장.
3. 하단에 네 시간대 종합 설명과 '확인할 조건 / 해석이 바뀌는 조건'. 동일 가격 설명을 네 번 반복하지 않는다.

작도와 설명을 연결한다. 설명을 선택하면 해당 선·구간을 강조하고 앵커 봉과 선정 이유를 보여 준다. 중요한 가격대에는 작은 라벨을 붙이고 라벨 겹침을 피한다. 차트 간에 동일한 색·선 의미를 유지한다.

지원 상호작용은 줌/이동, 개별 카드 확대, 작도 종류 표시 전환, 현재 분석 구간으로 복귀이다. 네 시간대의 확대 범위를 강제로 동일하게 동기화하지 않는다. 수동 작도 편집기, 실시간 틱 재분석, 사용자별 자동 매매 신호·알림은 별도 후속 범위다.

테마는 기존 보고서의 `--editorial-*` / 차트 토큰에 연결한다. 테마 전환 시 Canvas 배경, 축, 격자, 캔들, 거래량, 구간 투명도, 텍스트/툴팁을 같이 갱신하고 줌 상태를 유지한다. 지지/저항은 색만으로 구분하지 않고 라벨과 선 종류를 함께 사용한다.

데스크톱 카드의 차트 높이는 약 260~320px부터 실물로 조정한다. '한 페이지'를 한 화면 높이에 억지로 맞춰 글씨를 줄이지 않는다. 모바일은 1열과 카드 확대를 제공한다. 키보드/스크린리더 사용자를 위해 구간 가격과 조건 텍스트를 DOM에 둔다.

PDF도 동일한 산출물을 정적 SVG로 변환해 두 번째 페이지에 넣는다. 웹 캔버스 캡처를 PDF 발행의 필수 의존성으로 만들지 않는다. PDF에서는 표시 작도 수와 문장을 줄여 인쇄 크기에서 읽히게 한다. 차트 데이터가 없을 때는 그 상태를 텍스트로 전달하고 PDF 전체 생성을 계속한다.

## 10. 적정 수준의 검증

- 결정적인 경계만 회귀 테스트: 미래 봉 배제/스윙 확인 시점, 주봉·세션·분할 조정, 작도 좌표·상태, 유효하지 않은 선택 해설의 부분 복구, 기존 보고서 호환, 주봉 누락에도 실제 보고서 발행 성공.
- 실제 API 기반 리서치는 NVDA/AAPL/TSLA 세 종목으로 확인한다. 각 종목의 현재 추세를 미리 가정하지 않는다. 횡보/이력 부족은 작은 고정 데이터로 보완한다.
- 완성된 차트를 사람이 직접 보고 다음을 확인한다: 선이 실제 앵커에 붙는가, 같은 정보의 선이 과다하게 겹치지 않는가, 각 작도에 이유가 있는가, 다음 봉 조건과 무효화가 명확한가, 네 시간대 종합이 단순 나열을 넘는가.
- 데스크톱 다크/라이트, 모바일, PDF와 차트 한 시간대 실패만 실제 UI에서 확인한다. 의미 없는 전체 테스트 반복이나 수십 개 종목 일괄 생성은 하지 않는다.
- 이 검증은 기능 정확성과 설명 유용성을 확인한다. 예측 승률·수익성을 입증하는 검증과 혼동하지 않는다. 최초에는 결과를 관측할 수 있는 조건과 기준 시각을 저장하고, 예측 성능 수치를 표시하려면 이후 별도의 시계열 평가를 한다.

## 11. 구현 전에 사실 확인이 필요한 사항

- 직접 주봉 요청의 실제 응답, 4시간봉 시작/종료 기준, 진행 중인 봉의 표시 의미. 공식 문서 지원 여부는 확인했으며 계정별 실제 응답 확인은 아직 하지 않았다.
- 현재 `rights.ts`의 InsightSentry 공개 surface는 `derived_values_with_provider_attribution` 중심이다. 캔들 화면 표시/저장/PDF가 현재 구독 범위에 포함되는지 기존 계약·설정을 확인하고 공개 계약을 맞춰야 한다. '정규화했으므로 원본 캔들 표시가 자동 허용된다'고 간주하지 않는다. 데이터 API 키를 브라우저에 노출하지 않는다.
- 새 페이지는 전체 리서치와 시장 팀 리서치에 붙이는 것으로 계획했다. 별도 '차트 리서치만 생성' 진입점은 이번 페이지의 데이터/분석 계약을 재사용해 후속 기능으로 확장할 수 있다.
