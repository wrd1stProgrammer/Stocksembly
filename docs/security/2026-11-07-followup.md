## Request budgets

Production ingress is Client -> ALB -> nginx -> Next.js. nginx appends the ALB
peer to X-Forwarded-For, so the default trusted hop count is two. A single trusted
proxy deployment must explicitly set STOCKSEMBLY_TRUSTED_PROXY_HOPS=1. The web
port must accept traffic only through the trusted ingress; forwarded headers
alone cannot authenticate the sending proxy.

Budgets remain per process, with a route-wide backstop. Rejected per-client
requests no longer consume other clients' route budget. Aggregate ingestion is
limited to 120/minute and onboarding demos to 30/minute per client/process.
Existing aggregate body-size and event schema validation are retained.

## IAM rollout prerequisite

Before merging/deploying this change, an AWS administrator must grant the
existing GitHub deployment role GetSecretValue and PutSecretValue on the exact
web-bootstrap secret ARN. The runtime role receives GetSecretValue only.
The updated configure-scaling-access.py grants deploy access before restricting
runtime access. OPERATIONS_BUCKET must identify the operations bucket, rather
than the separate static CDN bucket.

Deploy the new role-deploy.sh and pipeline together. CI sanitizes the existing
bootstrap config after a healthy web rollout and before advancing the ASG image.
Provider secrets are loaded independently by each instance. Existing database
settings are retained. Sentry runtime values and analytics flags are supplied
from the same CI configuration used for serving instances.

Check effective IAM permissions, including other attached policies, after
applying the policy change. Confirm a new ASG instance can read configuration,
retrieve provider credentials and become healthy. No extra instance is started
by this code change.
