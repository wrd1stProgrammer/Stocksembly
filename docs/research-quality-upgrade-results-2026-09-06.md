## 구현한 공통 변경

1. **질문 명세와 근거 선택.** 원래 질문·목적·핵심 쟁점·인용으로 확인된 제품/사건 용어를 저장하고 전문 조사→팀 합의→감사→최종 편집에 전달한다. 원문 앞 12,000자 밖의 질문 관련 구간도 위치와 함께 선택한다.
2. **최신 사업 자료.** 최신 실적 발표 8-K와 같은 공시에 실제로 연결된 HTML 실적 첨부를 확보한다. Cybercab을 보안 사건으로 해석하던 문제 대신 SEC의 생산 개시 문맥을 전달한다.
3. **재무·거시 자료 연결.** 동일 기간의 분기/누적/연간 값을 묶고, 모델 입력의 중복 메타데이터만 줄인다. 실제 수집한 Treasury/BLS 최근 관측값도 원래 단위·관측일을 보존해 검증 레지스트리에 등록한다. 지수 수준을 임의 물가상승률로 변환하지 않는다.
4. **수치 재시도 복구.** 오류 코드뿐 아니라 거절된 주장과 선택한 지표를 같은 job/run의 다음 시도에 전달한다. 현금전환율 뒤의 ‘매출채권 증가’를 매출 성장률로 오인하던 검사를 문장/절의 지표에 연결했다. 잘못된 수치는 계속 거절한다.
5. **반론과 후속 조사.** 추가 조사에 감사 가능한 웹 경로를 연결하고 실제 조사 답변/미해결 사항을 원래 주장 담당자에게 전달한다. 팀 합의 입력에는 전체 주장 분류, 반론 삭제 금지, 정확한 수정 출처를 포함한다. 검증 실패를 전체 주장 자동 수용으로 바꾸던 fallback은 제거했다.
6. **결론과 감사.** 의미 감사 입력에 원래 질문·명세·수정된 최종 주장·반대 관찰·반증 조건을 넣었다. 팀 합의가 최종 방향·주 주장·반론·변경 조건을 decisionPacket으로 함께 만들고 개별팀 발행에 사용한다. 저장 호환 스키마와 새 모델 실행용 필수 스키마를 분리했다.
7. **최종 편집과 화면.** 최종 모델에 실제 내부 JSON 스키마를 전달하고 장기 질문의 변경 조건에 사업/현금흐름 관찰을 우선한다. Q&A는 최대 5개·같은 주장 최대 2개로 줄였다. 상단은 질문의 답→근거→반론→변경 조건 순서로 조정했고, 근거 카드에 반대 관찰이 들어가던 오류를 수정했다.

조사 명세 호출 1회가 추가됐다. 모델 종류는 유지하고 합의·의미 감사·최종 편집의 추론 설정을 medium으로 높였다. 그 외 조사 횟수/재시도 상한은 유지했다. decisionPacket과 최종 스키마 전달에는 별도 모델 호출을 추가하지 않았다.

## 원문 평가

**MSFT · 7점.** 유료 좌석과 Azure 매출로 실제 채택을 설명하고, 현금창출 여력과 AI 사업별 증분 투자수익률을 구별한다. 장기 질문과 핵심 변경 조건도 연결된다. 다만 반복되는 해자 주장, 일반적인 경쟁 위험, 보조 주장의 반증 방향, 장기 보유 질문에 섞인 신규 진입 Q&A가 남는다. [Microsoft 실적 원문](https://www.sec.gov/Archives/edgar/data/789019/000119312526323632/msft-ex99_1.htm)과 주요 채택/재무 수치를 대조했다.

**NVDA · 6.5점 유지.** 최신 이익과 현금흐름 차이, 매출채권 회수·재고·약정을 구분하는 분석은 유용하다. [NVIDIA CFO 설명](https://www.sec.gov/Archives/edgar/data/1045810/000104581026000073/q2fy27cfocommentary.htm), [분기 실적 원문](https://www.sec.gov/Archives/edgar/data/1045810/000104581026000073/q2fy27pr.htm)과 주요 수치를 확인했다. v6은 긍정 결론에 현금흐름 증가를 ‘반론’으로 붙였다. v10에서는 반론이 현금 전환 약화로 바로잡혔으나 변경 조건은 여전히 ‘재무상태가 견조하다는 판단은 유지’하는 조건이다. 현금전환율의 긴 소수도 그대로 노출됐다. 새 묶음은 조립 오류를 줄였지만 같은 모델의 자기검토만으로 논리 오류를 막지는 못했다.

**TSLA · 6.5점 유지.** 생산 개시와 유료 운행·수익화를 구별하고 장기 증액 질문에 답한다. 사업/수익성 자료가 늘었고 마지막 본문의 변경 조건은 자본배분·현금흐름을 다룬다. 그러나 핵심 반증에 ‘마진이 회복되면 마진 압박이 일시적이라는 판단이 약화’된다는 반대 방향 문장이 남는다. 의미 감사가 이 오류를 차단하지 못했다. 단기 차트가 근거 분석의 큰 비중을 차지하고, 시장팀 판단 칸에는 판단 자체 대신 후속 검토의 메타 설명이 들어간다. [Tesla 실적 첨부](https://www.sec.gov/Archives/edgar/data/1318605/000162828026049213/exhibit991.htm)와 핵심 생산/재무 문맥을 확인했다.

최종 TSLA는 내부 스키마 누락은 해소됐지만 **중복 출처 ID 2곳 때문에 최종 편집의 deterministic fallback이 다시 실행됐다**. 실제 모델 초안은 더 일관된 사업/가치평가 설명을 작성했으나 그대로 발행되지 않았다. 추가 모델 호출 없이 저장된 초안을 읽기 전용으로 재생해, 중복 ID만 제거해도 이후 엄격한 근거 투영이 핵심 문장을 다시 고르는 것을 확인했다. 따라서 ‘중복만 지우면 해결된다’는 수정은 넣지 않았다. 원본/발행본을 보존했고 이 재생 결과는 여섯 번째 생성본으로 세지 않는다. 근거: `.artifacts/quality-evaluation/chair-transport-replay.json`.

## 다음 품질 상승에 필요한 미완료 항목

1. **결론 단위의 독립 의미 검사.** `departmentRoundOutput.ts`의 구조/수치 확인과 별개로, `publicSummary + decisionPacket`의 반론 방향 및 변경 조건을 원문 근거와 함께 검사해야 한다. 현재 같은 합의 호출에 넣은 자기검토 지시로는 NVDA 반증 오류가 남았다. 별도 감사 도입 시 정식 logical job·입력 해시·예약·재시도 예산을 배정해야 하며 같은 예약으로 몰래 추가 모델 호출을 해서는 안 된다. 반증 발생을 가정했을 때 최종 결론을 유지/강화하는 출력은 반증으로 통과시키지 않는 것이 완료 기준이다.
2. **계산 정밀도와 독자 표시 정밀도 분리.** `specialistPromptRequest`/재무 근거 보드에 원본 값과 명시적 표시값을 나눠 주고, 퍼센트·통화별 자릿수 정책을 공통 발행/표시 경로에 적용해야 한다. 원본 Decimal 값·계산식·해시는 보존한다. 이번 NVDA의 긴 현금전환율은 표시 실패다.
3. **질문 목적에 맞는 출력 선택.** `anticipatedQuestionsPublication.ts`가 researchBrief.objective를 받아 재무 건전성 질문에서는 운전자본·부채/약정·현금 회수를 우선하도록 해야 한다. 현재 개수와 중복만 줄였으며, 목표가/애널리스트 쏠림 Q&A가 계속 앞선다. 일반 재무/사업 질문을 자동으로 신규 진입 행동에 매핑하는 표시도 분리해야 한다.
4. **8점에 필요한 경제적 분석.** 사업별 채택·수익화·단위경제성에 대한 검증 가능한 시계열과, 가격이 요구하는 성장/마진/재투자 가정을 연결한 계산이 필요하다. 단순 현재가÷컨센서스 EPS나 목표가 차이를 가격 내재 기대 분석이 완성된 것으로 취급하지 않는다. 데이터가 없으면 항목별 미확인 상태와 이를 해소할 원천을 표시한다.

5. **최종 편집과 출처 투영의 분리.** `chairSynthesisV3.ts`/`chairSynthesisHandler.ts`에서 중복 인용 같은 복구 가능한 형식 오류와 실제 출처 불일치를 구별해야 한다. 문장 ID로 출처 집합을 도출하고 실제 내용의 근거를 검증하되, 올바른 본문이 기계적 원문 조합으로 돌아가는 상황을 줄여야 한다. 반증 방향 오류가 있는 문장을 원문이라는 이유로 다시 채택해서도 안 된다. 저장된 실제 초안과 발행본 비교를 회귀 자료로 쓸 수 있다.

이 항목들은 이번에 구현 완료한 것으로 주장하지 않는다. 실제 새 원문을 읽고 확인한 7~8점 목표의 남은 장애물이다.

## 종료 및 재개 위치

최종 생성 5개와 평가는 완료했다. 목표 점수는 미달이다. 추가 변경 시 위 미완료 항목 중 결론 단위 의미 검사와 최종 편집/출처 투영을 먼저 다룬다. 기존 5개 결과를 새로운 생성 결과로 다시 세지 않는다. 비밀 값은 문서와 도구 출력에 포함하지 않았다.
