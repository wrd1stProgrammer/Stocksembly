01 · Processing

데이터가 리포트가 되는 과정

에이전트가 인터넷을 자유롭게 훑는 방식이 아니라, 먼저 근거 묶음을 봉인한 뒤 그 범위 안에서 분석합니다.

01기업 식별티커를 SEC CIK·법인명·거래소와 연결합니다.
02병렬 수집SEC, InsightSentry, BLS, 미 재무부 데이터를 동시에 요청합니다.
03정규화·검증형식, 시점, 출처, 단위와 콘텐츠 해시를 확인합니다.
04스냅샷 봉인기준 시각 이후 들어온 데이터가 섞이지 않도록 근거를 고정합니다.
05팀별 분석팀마다 필요한 데이터만 받아 메모·반론·최종 판단을 생성합니다.

05 · Team routing

팀별로 어떤 데이터를 받나?

전체 리서치는 네 팀을 모두 실행하고, 개별팀 리서치는 선택한 팀의 데이터 계약만 사용합니다.

팀주요 데이터답하려는 질문
시장팀가격·거래량, 현재가, 시장 뉴스, 비교기업, 펀더멘털, 국채, BLS, 대량보유자지금 상승·하락 타이밍이 시장과 상대강도로 확인되는가?

06 · Conditional & inactive

조건부

옵션 데이터

insightsentry_options — 계약과 코드 자리는 있지만 현재 rollout이 꺼져 있고 권한도 요청하지 않습니다.

대기 어댑터

Alpaca 일봉

alpaca_market_data — 3년 일봉과 SMA·RSI·MACD 계산 코드는 있으나 현재 초기 파이프라인의 기본 시세는 InsightSentry를 사용합니다.

이름과 실제 내용이 다른 한 가지

sec_institutional_holdings라는 내부 이름은 다소 넓습니다. 현재 실제 기본 수집은 13F 전체 기관 포트폴리오가 아니라, 해당 기업의 SEC 제출 목록에서 확인되는 Schedule 13D·13G 대량보유자 공시입니다.

07 · Guardrails

데이터 사용 원칙

시점 고정

리서치 기준 시각 이후 공개되거나 수집된 자료가 현재 판단에 섞이지 않도록 acquisition cutoff와 snapshot을 기록합니다.

원문과 정규화본 보존

InsightSentry 응답은 원본 묶음과 분석용 정규화 데이터를 함께 보관하고 서로의 부모 해시를 연결합니다.

출처·해시 연결

URL, 제공자, 조회시각, 문서 번호, 콘텐츠 해시를 근거 artifact와 함께 저장해 어떤 데이터에서 나온 주장인지 추적합니다.

부재를 숨기지 않음

데이터 계열별 available·unavailable 상태와 limitation을 남깁니다. 다만 현재가와 차트 데이터는 필수이므로 없으면 리서치를 시작하지 않습니다.

이 문서는 initialCollectionData.ts, insightSentryInitialCollection.ts, evidenceCoreSchemas.ts, teamCoreData.ts의 현재 구현을 기준으로 작성했습니다. API 제공 범위나 파이프라인 코드가 변경되면 함께 갱신해야 합니다.
