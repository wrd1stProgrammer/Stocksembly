# 발행 안정성과 대표 회의 흐름 수정

기준 커밋: d66a7c4 (PR #51 배포본). 브랜치: codex/publication-and-committee-flow.

## 확인된 실패

운영 실행 a1b98b02-2958-4100-90fc-3f731e7e9599는 의미 감사 뒤 최종 의장 단계에서 네 번 실패했다. 모델 결과 형식은 유효했다. 본문은 숫자를 정리하지만 decisionBrief와 원문 복구 경로에는 66.23710000935347% 같은 숫자가 남아 invalid_directional_brief로 거부됐다. 같은 결정적 오류에 모델을 재호출했고 예외 원인은 chair_synthesis_missing으로 감춰졌다.

## 구현 순서

1. 완료: 본문/최종 판단/복구/정식 v3 문장 전체에 일관된 숫자 표기 정리를 적용한다. 출처와 수치의 의미를 보존한다. 표시 문제와 근거 오류를 구분하며 반복 모델 호출로 고칠 수 없는 projection 오류는 명시한다.
2. 완료: 실제 발행 함수를 연결한 SQLite 회귀 시나리오로 영어/한국어 고정밀 근거가 한 번의 의장 호출 뒤 report_versions 및 report_published까지 도달하는지 확인한다. 운영 실패 입력도 재생한다.
3. 완료: 대표마다 한 상대와의 방문 토론만 연출한다. 나머지 실제 반론/후속 답변은 중앙에서 발언하게 하며 완료된 대표는 먼저 중앙에 앉는다. 중앙 발언은 발행 전 확보한 이벤트를 사용한다.
4. 완료: 발행 결과 접근을 애니메이션 완료와 분리한다. 관련 회귀 테스트와 실제 브라우저에서 방문→선착석→중앙 발언을 확인한다.
5. 인계 절차: 변경 파일만 커밋·푸시하고 PR/CI를 확인한다. 운영 배포와 실패 실행 재개는 실제 상태와 구분해 보고한다.

## 범위

omo/하위 에이전트 없이 진행. 기존 작업 공간과 자료 보존. 테스트는 변경 경로 위주로 수행. 운영 원본은 읽기 전용이며 Git에 포함하지 않는다. 근거 없는 사실/외부 권한/계보 검사를 약화하거나 성공으로 위장하지 않는다.

## 구현 및 검증 결과

- 최종 판단의 세 문장, 원문 복구, canonical v3의 사용자 문장에 기존 숫자 표기 정리를 동일하게 적용했다. `66.23710000935347%`는 `66.24%`로 표시하며 원본 근거는 바꾸지 않는다.
- 결정적 projection 오류는 먼저 감사된 근거로 복구한다. 복구도 불가능하면 구체적인 원인을 보존하고 같은 모델을 네 번 재호출하지 않는다. 일시적 실행 오류의 기존 재시도는 유지한다.
- 운영 실패 실행의 저장된 의장 응답 4개 및 결정적 복구 결과를 읽기 전용으로 재생하여 모두 최종 projection에 통과했다. 이 검증은 운영 실행을 재개하거나 발행한 것이 아니다.
- 영어 정상 모델 / 한국어 잘못된 모델 출력 두 경우 모두 실제 `publishAuthoritativeReportForRun`을 연결해 `report_versions` 1건, `report_published` 1건, 한 번의 의장 호출을 확인했다. 고정밀 근거도 최종 판단에 정상 표시된다.
- 복구 불가능한 projection 오류를 주입한 회귀 테스트는 원인 코드 보존, 한 번의 모델 실행, 발행 없음, 호출 한도 소진 없음으로 통과했다.
- 관련 backend 테스트 39개 통과 후 오류 분류 테스트를 추가한 chair v3 파일 20개도 통과했다. 방문/중앙 흐름 및 기존 대화/물리 이동 테스트 4파일 15개 통과. TypeScript 검사 통과.
- 실제 브라우저의 `/research-fixture/NVDA?scene=continuity&lang=ko`에서 첫 쌍이 중앙에 앉고 두 번째 쌍은 부서 방문을 마치는 장면, 이후 다섯 명이 중앙에 모인 상태에서 대표 발언/응답을 확인했다. 브라우저 error 로그 없음. 이 페이지는 개발 전용이며 표시 문장은 fixture이다.
- 발행 결과 접근은 애니메이션 대기와 분리했다. 실제 반론 이벤트가 있는 경우 저장된 팀 입장을 뒤늦게 별도 회의처럼 추가하지 않는다. 백엔드 토론/조사 호출 수는 추가하지 않았다.
- 로컬 Next dev는 공유 node_modules 심볼릭 링크를 지원하는 webpack으로 확인했다. 배포용 정식 빌드는 PR CI가 검사한다. 검사 로그는 무시되는 `.stocksembly-verification/publication-committee/`에 보관한다.

운영 반영 여부는 PR 병합 및 배포 결과와 구분한다. 운영 기존 실패 실행은 변경하지 않았다.
