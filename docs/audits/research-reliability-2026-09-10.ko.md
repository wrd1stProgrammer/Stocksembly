# 리서치 완료 안정화 · 2026-09-10

동시에 시작한 AAPL·MSFT·NVDA·AMZN 전체 리서치가 모두 보고서 발행을 마쳤다.
검증 도중 발견한 오류를 수정하고 같은 실행을 복구한 결과다. 무중단 첫 시도 성공률이나 평균 처리 시간을 측정한 시험은 아니다.

## 최신 코드 및 작업 범위

작업 시작 시 로컬 기준 main, 원격 main, 운영 web/worker 이미지가 모두
`3140a398ca4e42023789218509d56f72217ac84f`임을 확인했다.
원래 checkout의 미커밋 파이프라인 변경도 대조했다. 원래 작업 디렉터리는 수정하지 않았다.

변경은 `Stocksembly-research-capacity`의 `codex/research-capacity-routing` 브랜치에 있다.
커밋·push·운영 배포는 하지 않았다. 이전에 구현한 CLI 4건 + API 6건 + 초과 대기열 배분은 유지한다.
이번 실서버 검증은 모델 API를 비활성화하고 기존 Pro 로그인만 사용했다.

## 수정한 실패 경로

- **재시도 계산:** 일시적 실행 실패를 내용 재작성 횟수로 세지 않는다. 이미 사용한 재작성은 초기화하지 않는다. 아티팩트당 3회, 전체 12회 재작성 한도는 유지한다.
- **복구 여유:** 주요 워크플로 예약 상한을 65회로 구성했다. 수집 1 + 필수 25 + 선택 3 + 재작성 12 + 일시적 재시도 여유 24다. 평소 모두 소비한다는 뜻이 아니다. 뉴스 분류·기획 등 보조 호출은 별도이므로 전체 계정의 CLI 호출 횟수 상한은 아니다. 순번은 환불하거나 재사용하지 않는다.
- **부분 분석 보존:** 검증할 수 없는 비율 문장을 제외하고, 검증된 다른 주장이 남으면 제한사항을 명시해 진행한다. 누락된 관점을 새로 만들어 채우지 않는다. 근거가 모두 사라지거나 반론 참조가 끊기면 그대로 거절한다. ratio와 percent 단위도 구분한다.
- **시세 호출 제한:** 제공업체의 재시도 시각을 보존하고 대기 요청에 공유한다. 재시작 시 대기 상태를 복원하며 429 이후 동시 요청을 1개로 낮춘다. 수집은 작업별 최대 8회, 지수 백오프를 사용한다.
- **남은 보조 작업:** 필수 시세 요청을 모두 기다린 뒤 실패를 반환한다. 필수 데이터가 확보되기 전에는 보조 AI 작업을 시작하지 않아 이전 작업과 재시도가 겹치지 않게 한다.
- **worker 중단:** worker 종료로 중단된 작업은 재시도 대기로 보존한다. 실제 사용자 취소는 구분하여 종료한다.
- **Docker 잠금:** PID 1 재사용으로 잠금이 영구 점유된 것처럼 보이던 문제를 전용 SQLite 잠금으로 해결했다. OS가 강제 종료 시 잠금을 해제한다. 잠금 DB는 실행 중 삭제하지 않는다. 최초 배포는 구버전 worker를 먼저 중지해야 한다.
- **빈 질문 재시작:** 종목만 입력한 정상 요청의 빈 질문은 번역 보충 대상에서 제외한다. DB 질문을 변경하거나 모델을 호출하지 않는다.
- **최종 발행 근거:** 본문 6개 섹션에 선택된 주장만으로 발행 권한을 다시 만들던 오류를 수정했다. 검증 후 보고서에 보존된 전체 주장 집합을 사용한다. NVDA의 검증된 재무팀 주장 2개가 누락으로 오인되던 실제 사례가 해결됐다.
- **수동 복구 안내:** 예약 상한을 소진한 요청을 재접수해 즉시 실패시키지 않는다. 추가 모델 호출이 필요 없는 발행 단계 복구는 허용한다.
