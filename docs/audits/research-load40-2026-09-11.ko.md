## 오류와 개선점

- GOOGL에서 실행 파일 확인(`environment/binary_verify`) 일시 오류4회 발생. 모두 자동 재시도되어 완료. 외부 모델 rate limit 또는 메모리 부족으로 판정된 오류는 아니다.
- AVGO 수치/지표 불일치1회와 부문 종합 미완성1회가 출력 보정으로 처리됐다.
- 모델 재작성 합계7회: GOOGL1, META2, AVGO2, TSLA2. 워크플로 단계 간 추가 기다림을 포함한다.
- 최종 발행 실패0회. 모델 기록은 전부 `gpt-5.6-luna`, API 모델 호출 없음.
- 리서치당3개 고정 상한을10개로 늘려 각10개까지 실제 배분됨을 확인했다. 하지만 실제 Codex 프로세스 수와 실행 상태 작업 수 차이가 크므로, 다음 성능 개선은 상한 추가 확대보다 작업 준비/실행 파일 검사와 단계별 대기 시간 계측이 우선이다. 기존에 확인한 반복 reconcile의 증거·DB 검증 비용도 후보이며 이번에 변경하지 않았다.

## 코드·실행 조건

- `src/research/domain/researchExecution.ts`의 `jobsPerRun`을 3에서 10으로 변경했다.
- 실제 SQLite 회귀 검사는 4개 실행에 각각 11개 작업을 준비하고, 10개씩 공정하게 임대하며 초과 작업은 대기하는지 확인한다. 기존 상한 3에서 실패를 확인한 뒤 수정했다. 슬롯 보충 검사를 포함한 관련 테스트 4개, 워커 타입 검사·빌드·diff 검사가 통과했다.
- 검증 환경에만 `STOCKSEMBLY_GLOBAL_CODEX_PROCESSES=40`, `STOCKSEMBLY_CODEX_API_ENABLED=0`을 적용했다. 저장소의 전역 기본값 12는 유지한다. 배포 시 40을 사용하려면 명시적인 환경 설정이 필요하다.
- 실행 파일 SHA256: `d0b2e06e6b0b6501cd52ea82db17c12862960b2101e5d7d261db1aec7cb1cedb`.
- 운영과 같은 EC2에서 별도 컨테이너·SQLite·CAS를 사용했다. 운영 이미지 기반 Node20, 같은 Pro 인증·실제 데이터 공급자·SEC 설정으로 실행했다. 컨테이너 메모리 상한은 6GiB이며 호스트의 2vCPU를 공유했다.
- 서로 다른 4개 principal로 실제 request admission repository를 호출했다. 빈 질문·영문·전체 위원회 리서치 조건이다. 로그인·UI·HTTP 접수 앞단은 재생하지 않았으며, 핵심 리서치 실행 부하를 측정했다. 운영 사용자의 데이터와 결제 상태는 변경하지 않았다.
