01EXECUTIVE SUMMARY

무엇을 만드는가

심볼 하나를 입력하면 여러 AI가 시장·기업·재무·가치평가·차트·위험을 독립적으로 조사하고, 회의와 반론을 거쳐 출처가 연결된 하나의 리서치 문서를 만드는 서비스다.

제품 한 문장 여러 전문 AI가 한 종목을 독립적으로 조사하고 서로 반박한 뒤, 사용자가 스스로 판단할 수 있는 근거 지도를 만든다.
INPUT

종목 하나

회사명·심볼·종목코드로 미국과 한국 상장사를 검색한다.

PROCESS

AI 리서치 조직

역할별 분석, 출처 검증, 의견 충돌, 위원회 종합 과정을 보여준다.

OUTPUT

판단 가능한 리포트

기업 상태, 기대와 현실의 차이, 위험, 시나리오, 확인할 변수를 제공한다.

02PROBLEM & VALUE

정보는 넘치지만 판단의 구조가 없다

사용자 문제

  • 공시, 실적 자료, 뉴스와 차트를 따로 찾아야 한다.
  • 숫자가 좋아도 현재 가격에 기대가 얼마나 반영됐는지 알기 어렵다.
  • 일반 AI 답변은 근거 출처와 반대 논리가 약하다.
  • 긴 분석 대기시간은 보통 의미 없는 로딩으로 느껴진다.

제품 해법

  • 데이터를 한 번에 수집하고 동일한 시점의 스냅샷으로 분석한다.
  • 서로 다른 역할이 독립적으로 판단한 뒤 의견 차이를 공개한다.
  • 모든 핵심 주장에 원문과 기준 시각을 연결한다.
  • 분석 대기를 AI 연구소가 움직이는 제품 경험으로 바꾼다.
03PRIMARY USERS

첫 고객은 한국의 미국주식 개인투자자

탐색형 투자자

관심 종목을 발견했지만 어디부터 조사할지 모른다. 10초 요약과 핵심 질문이 중요하다.

공부형 투자자

직접 판단하고 싶지만 영어 공시와 재무 분석이 부담스럽다. 원문 연결과 쉬운 설명이 중요하다.

바쁜 직장인

여러 출처를 따라갈 시간이 없다. 변화 요약, 이벤트 일정, 이전 분석과 비교가 중요하다.

비대상: 초단타 신호, 자동매매, 옵션 주문, 개인별 포트폴리오 지시를 원하는 사용자.

04PRODUCT PRINCIPLES

제품이 흔들리지 않게 하는 여섯 원칙

  1. 근거가 먼저다. 출처 없는 주장은 결과 리포트에 포함하지 않는다.
  2. 의견 차이를 숨기지 않는다. 합의와 미합의를 모두 보여준다.
  3. 사고 과정 대신 작업 근거를 보여준다. 원시 추론이 아니라 자료 조회·계산·검증 기록을 스트리밍한다.
  4. 모르는 것을 표시한다. 사실, 해석, 미확인 영역을 구분한다.
  5. 매매를 명령하지 않는다. 투자판단을 대신하지 않고 기업의 상태와 확인 조건을 제공한다.
  6. 재분석할수록 가치가 커진다. 지난 분석 이후 무엇이 달라졌는지를 핵심 재방문 이유로 만든다.
05MARKET SCOPE

양쪽을 지원할 구조, 미국부터 출시

공통 분석 엔진 위에 시장별 데이터 어댑터와 분석 규칙을 둔다. 미국주식용 로직을 한국주식에 단순 번역해서 사용하지 않는다.

06CORE USER FLOW

검색에서 리포트까지 다섯 단계

  1. 통합 종목 검색

    회사명, 영문 심볼, 한국 종목코드를 지원한다. 결과에는 거래소와 국가를 명확히 표시한다.

  2. 분석 브리핑

    회사·시장·데이터 기준 시각을 확인하고, 담당 에이전트와 분석 계획을 생성한다.

  3. 부서별 독립 조사

    시장, 기업, 재무, 가치평가·차트, 위험 분석이 같은 데이터 스냅샷을 기반으로 독립 실행된다.

  4. 교차 검증과 회의

    근거 감사가 숫자와 출처를 검사하고, 리스크 분석가가 반대 논리를 제시한다. 위원장이 합의와 충돌을 정리한다.

  5. 전문 리포트

    10초 요약, 핵심 근거, 재무·가치평가, 시나리오, 미확인 영역, 출처를 하나의 읽기 흐름으로 제공한다.

표시할 것

  • 자료를 가져오는 행위
  • 계산·비교·검증 상태
  • 에이전트 간 질문과 반론
  • 출처 링크와 진행률

표시하지 않을 것

  • 모델의 원시 사고 과정
  • 실제 작업과 무관한 가짜 로그
  • 완료 후 시간을 끄는 애니메이션
  • 사용자가 취소할 수 없는 대기
10REPORT OUTPUT

결론이 아니라 판단 가능한 구조를 제공한다

  1. 10초 요약: 기업 현재 상태 한 문장, 자료 수, 기준 시각.
  2. 상태 지도: 사업 성장, 수익성, 재무 안정성, 가치평가, 가격 흐름, 위험.
  3. 긍정·우려 요인: 각각 3~5개, 모든 항목에 근거 연결.
  4. 위원회 결과: 합의된 내용, 합의하지 못한 내용, 핵심 논쟁.
  5. 전문 분석: 사업 구조, 재무 추세, 가치평가, 가격·차트, 촉매와 일정.
  6. 시나리오: Bull·Base·Bear의 조건, 사업 변화, 확인 지표.
  7. 사실 구분: 확인된 사실, 합리적 해석, 아직 알 수 없는 것.
  8. 변화: 지난 분석 이후 긍정·주의 변화.
  9. 근거: 출처 원문, 문서 위치, 데이터 기준 시각, 누락 데이터.
결과 카피 금지매수, 매도, 보유, 비중 축소, 분할매수, 진입가, 목표가, 개인 보유정보 기반 행동 권고를 기본 리포트에 넣지 않는다.
11SYSTEM ARCHITECTURE

AI보다 먼저 데이터와 작업 상태를 구조화한다

사용자 요청
  → 분석 Job 생성 및 중복 요청 결합
  → 시장별 Data Adapter가 원문 수집
  → 동일 시점의 immutable Data Snapshot 생성
  → Agent Worker 2~3개 병렬 실행
  → Risk Analyst 반론
  → Evidence Auditor 검증
  → Research Chair 종합
  → JSON Schema 검증
  → UI 스트리밍 및 Report 저장

초기 CLI 운영 원칙

  • 웹 요청에서 CLI를 직접 실행하지 않고 작업 큐와 워커를 사용한다.
  • 서버 전체 동시 CLI 실행 수를 2~3개로 제한한다.
  • 같은 종목과 같은 데이터 기준 시각의 요청은 결과를 공유한다.
  • AI는 웹을 자유롭게 탐색하지 않고 정리된 데이터 스냅샷만 받는다.
  • CLI 실행부는 Provider 인터페이스 뒤에 두어 API 방식으로 교체 가능하게 한다.
  • 작업별 임시 디렉터리, 읽기 전용 데이터, 타임아웃, 취소를 지원한다.

  • 실시간 호가와 초단타 신호
  • 옵션 분석
  • 소셜 감성 점수
  • 정밀 목표주가
  • 전 종목 한국시장 동시 출시

구현 순서

  1. 정적 결과 리포트와 데이터 계약
  2. 검색과 분석 Job API
  3. 에이전트 실행과 JSON 검증
  4. 스트리밍 오피스 UI
  5. 저장·공유·변경 비교
  6. 한국시장 어댑터
15ACCEPTANCE CRITERIA

완료를 판단하는 실제 조건

  • AAPL, NVDA, TSLA 등 유효한 심볼을 검색하고 올바른 기업을 선택할 수 있다.
  • 존재하지 않는 심볼은 명확한 오류와 다시 검색할 방법을 제공한다.
  • 분석 진행 상태가 서버 Job 상태와 일치하며 취소와 재시도가 가능하다.
  • 각 결과 주장에는 하나 이상의 검증된 evidence ID가 연결된다.
  • 데이터가 부족하면 AI가 임의로 채우지 않고 미확인으로 표시한다.
  • 완료 리포트에는 요약, 상태, 긍정·우려, 논쟁, 재무, 가치평가, 시나리오, 출처가 있다.
  • 375px, 768px, 1280px에서 핵심 작업이 가로 스크롤 없이 가능하다.
  • 키보드만으로 검색, 분석 시작, 로그 탐색, 리포트 이동이 가능하다.
  • 분석 중 화면은 reduced-motion에서 캐릭터 이동 대신 상태 목록을 제공한다.
  • 리포트를 인쇄하거나 PDF로 저장했을 때 출처와 표가 읽을 수 있다.
16AI BUILD HANDOFF

바이브코딩 AI에게 그대로 전달할 프롬프트

아래 프롬프트와 이 HTML 문서를 함께 제공하면 된다. 실제 기술 스택을 이미 정했다면 첫 문단에 추가한다.

당신은 시니어 제품 엔지니어이자 핀테크 UX 엔지니어다.

첨부된 “AI Research Office 프로젝트 기획서”를 제품 명세의 단일 기준으로 사용해 MVP를 구현하라.

핵심 제품:
- 한국 투자자가 미국주식 심볼을 검색한다.
- 역할이 다른 AI 분석가들이 시장, 기업, 재무, 가치평가·차트, 위험을 독립적으로 조사한다.
- 진행 중에는 원시 chain-of-thought가 아니라 자료 조회, 계산, 검증, 반론과 출처를 공개 활동 로그로 스트리밍한다.
- Evidence Auditor가 출처 없는 주장을 제거하고 Research Chair가 합의와 의견 충돌을 종합한다.
- 결과는 매수·매도 명령이 아니라 기업 상태, 시장 기대, 긍정·우려, 재무 추세, 가치평가, 촉매, 시나리오, 미확인 영역과 출처를 보여주는 전문 리포트다.

구현 원칙:
1. 먼저 데이터 계약과 JSON Schema를 정의하고 UI를 그 위에 구현한다.
2. 웹 요청에서 CLI를 직접 실행하지 말고 Job Queue와 제한된 Worker를 사용한다.
3. 데이터 수집은 AI가 아닌 Adapter가 수행하고 Agent에는 immutable snapshot만 전달한다.
4. 모든 주장에는 evidence_id, source, freshness가 있어야 한다.
5. 존재하지 않는 종목, 데이터 부족, API 실패, 분석 취소, 시간 초과 상태를 설계한다.
6. desktop-first이지만 375/768/1280px에서 핵심 플로우가 작동해야 한다.
7. 키보드, visible focus, reduced motion, semantic HTML, WCAG 2.2 AA를 지킨다.
8. 매수·매도·보유·비중·진입가·목표가·개인별 행동 권고를 넣지 않는다.
9. 임시 mock data는 실제 API 응답과 같은 타입을 사용하고 한 곳에서 교체 가능하게 한다.
10. 기능을 실제 화면에서 검증하고 검색 성공·실패·분석 중·완료 리포트 시나리오를 테스트한다.

우선 구현 순서:
1) 결과 리포트와 mock data 계약
2) 통합 종목 검색
3) 분석 Job과 SSE/WebSocket 이벤트 스트림
4) 부서형 AI Research Office 화면
5) 결과 저장·공유·지난 분석 변경 비교

각 단계가 끝날 때 변경 파일, 실행 방법, 검증 결과, 남은 제한을 보고하라. TODO나 빈 화면을 남기지 말고 현재 범위의 흐름을 끝까지 완성하라.
